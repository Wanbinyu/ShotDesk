# 分镜成片台

版本 0.1.0。这是一份给以后改项目的人看的说明。怎么安装和点界面，看仓库根目录的 [README.md](../README.md)。

## 项目说明

分镜成片台是跑在本机的短视频工作台。一个项目里写剧本、放角色和场景、逐条出画面、配音、预览，最后得到一条成片和一份剪映草稿。浏览器只连 `127.0.0.1`，默认端口 `8775`。

它要解决的是来源不统一。一条片子里，有的镜头用工作台自己画，有的镜头交给外部视频接口，有的镜头是已经拍好的文件。这三种画面进了时间轴之后待遇相同：后面的拼接、字幕、预览和剪映草稿只认落在本机的那个 mp4，以及它的时长。

一条镜头在库里带着自己的来源，取值是 `builtin`、`external` 或 `import`。文件写好以后，下游用的是 `file_path` 和 `duration_ms`。所以以后加一种新的出片方式，应该做成新的适配器，而不是再做一条平行的时间轴。

三种来源现在分别是：

- 自带。Pillow 画一张 1080×1920 的静帧，ffmpeg 做缓慢推拉，再贴上配音。不下载视频模型。
- 外部。默认也在本地画一张占位图，并记下估价。设置改成 http 之后，才向填写的地址提交任务并轮询结果，下载回来再收成同样的画幅。
- 导入。复制上传的视频，收成 1080×1920、25 帧、立体声，保留原声，不再配一遍对白。

人要先点头，机器才出画面：

- 剧本还是草稿时，不能生成，也不能导入。
- 资产没锁定时，不能生成自带和外部镜头。导入只要剧本已经通过。
- 改角色、场景、道具或参考图，会取消资产锁定。
- 改镜头文案不会删掉已经生成的视频。界面比较修改时间和成片时间，提示画面还是上一次的。
- 工作台不自动发到任何平台。

自带和外部镜头最长 15 秒。更长的素材用导入，上限 180 秒。上传限制是视频 200MB、背景音乐 30MB、参考图 15MB。

这一版明确不做的事：不部署本地视频模型，不爬素材，不换脸，不做声音克隆，不无人值守发布。配音只用 Edge TTS；连不上就改成等长静音，镜头仍然能出。

估价是记账，不是账单。自带和导入记 0。外部按设置里的「分/秒」乘时长，占位模式记「占位估价」，http 模式记「估价」。

## 项目结构

```text
ShotDesk/
  app.py                 启动入口。准备数据库，绑定 127.0.0.1:8775，打开浏览器
  启动.bat               Windows 启动脚本
  requirements.txt       Pillow、edge-tts、pyJianYingDraft
  LICENSE                MIT
  README.md              怎么启动、一条片子怎么走
  docs/
    项目说明.md          本文件
    workbench.png        界面截图
  shotdesk/              服务和出片逻辑
  static/                浏览器里的页面，没有构建步骤
  tests/test_pipeline.py 关卡、三种来源、拼接、剪映、网页和外部下载
  data/                  运行后才出现，不进 git
```

`shotdesk` 里每个文件一件事：

| 文件 | 职责 |
| --- | --- |
| `server.py` | 标准库 HTTP 服务。页面、JSON 接口、上传和 `/files/` 都从这里进 |
| `db.py` | SQLite。项目、资产、镜头、导出记录。开了外键和 WAL |
| `script.py` | 空行分段，识别 `画面`、`对白`、`角色`、`运镜`、`时长`。不调用模型 |
| `pipeline.py` | 生成、导入、拼接、导出。数据库锁只包住读写，不包住 ffmpeg |
| `media.py` | 静帧、推拉、归一化、拼接、背景音乐、字幕。画幅 1080×1920，25 帧 |
| `voice.py` | Edge TTS。失败时写一条等长静音 |
| `provider.py` | 外部 http：`POST /v1/videos`，再轮询 `GET /v1/videos/{task_id}`，下载 mp4 |
| `jianying.py` | 用 pyJianYingDraft 写明文草稿，并探测本机剪映目录 |
| `settings.py` | `data/settings.json`。接口不回传密钥原文 |
| `sample.py` | 示例「雨夜送伞」。三条镜头依次是自带、外部、导入 |
| `errors.py` | `DeskError`。接口把它变成 400 和一句中文 |

页面是 `static/index.html`、`app.css`、`app.js`。脚本直接改 DOM，用 `data-act` 分发点击。有镜头在排队或生成时，大约每 1.2 秒拉一次项目；当时焦点在输入框里则跳过，避免打断编辑。

数据目录在数据库旁边。默认数据库是 `data/shotdesk.db`。

```text
data/
  shotdesk.db
  settings.json
  media/{项目id}/
    cards/          静帧
    silent/         还没贴配音的画面
    voice/          配音或静音
    shots/          这一条镜头的成片
    inbox/          刚上传、还没归一化的视频
    assets/         参考图缩略图
    bgm.mp3         背景音乐，后缀随原文件
  exports/{项目id}/
    preview.mp4
    subtitles.srt
    timeline.json
    clips/01.mp4    按时间轴顺序复制的镜头
    README.txt
```

`/files/` 只放 `data/media` 和 `data/exports` 下面的文件，路径先解析再判断是不是落在这两个目录里。

一次生成的顺序是：网页调用 `/api/shots/{id}/generate`，服务先把镜头标成排队并立刻返回，后台线程再跑 `produce_shot`。线程里先把状态改成正在生成，然后出画面、出声音、贴到一起，最后写成 `shots/shot-{id}.mp4`。批量生成会先把能做的镜头都标成排队，再在一个线程里按顺序做。失败写在镜头的 `error` 上，不会把整次批量停掉。

合成在成片页点下去之后同步做完：复制镜头、按顺序拼接、有背景音乐就以 0.18 的音量混进去、写字幕和时间轴。填了剪映草稿目录才额外写草稿。草稿有两条轨，名字是「画面」和「字幕」。

库里有四张表：`projects`、`assets`、`shots`、`exports`。项目上的 `aspect` 现在固定是 `9:16`，导出也固定是竖屏，这个字段还没有参与计算。

## 以后的改进方向

改的时候先保住这条约定：新的出片方式只负责交出一个 mp4 和时长。拼接、字幕、预览、剪映不要再按来源分叉。

可以接着做的，按对现在这条流程的影响排：

1. 画面适配器。自带推拉只是第一个适配器。以后可以把 ComfyUI、Wan 或其他本地模型接成另一种渲染，仍然走同一条镜头。模型本身不打进仓库，由使用者自己准备运行环境。外部接口现在只有一种提交再轮询的约定，以后可以加第二种供应商，下载后仍要归一化。
2. 时间轴。现在是整段顺序拼接，没有入出点、转场和音量包络。单条重做会整段替换。剪映草稿里也还没有独立的配音轨和背景音乐轨。
3. 画幅。库里已经有 `aspect`，导出仍写死 1080×1920、25 帧。要做横屏时，从这一处改静帧、归一化和剪映宽高，不要只改页面上的字。
4. 剪映新版本。现在写的是明文 `draft_content.json`。剪映 5 和一部分 6 能打开；更高版本如果改成加密草稿，就继续把成片和字幕当作可靠交付，草稿跟随 pyJianYingDraft 能写的格式。
5. 剧本助手。拆分现在是规则，没有语言模型。以后可以加一个可选的助手来起草稿，通过剧本的按钮仍然要人点。
6. 配音。可以换音色或换引擎。失败时仍应落成静音，而不是让整条镜头失败。不做从一段录音克隆声音。
7. 长任务。生成已经放到后台。合成、导入和写剪映草稿还占着同一次请求，片子长时页面会一直等。可以把导出也改成排队，页面只看状态。
8. 安装。现在依赖本机的 Python 3.11 和 ffmpeg，用 `启动.bat` 打开。以后可以做成带解释器的目录，避免使用者先装环境。

这些边界继续留着：不自动发布，不爬别人的视频当素材，不换脸，不做声音克隆。

测试命令是 `python -m unittest tests.test_pipeline`。现在覆盖剧本拆分、关卡、三种来源拼到一起、剪映草稿文件、网页生成、外部接口下载、去掉背景音乐，以及剪映目录探测。改适配器或时间轴时，先让这组测试继续能说明「三种来源进了同一条成片」。
